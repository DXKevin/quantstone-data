# Agent 工作交接

本文档是 Codex 与 DeepSeek Harness 在同一个项目目录中串行接力的当前状态记录。

长期架构与项目原则见 [项目架构、设计原则与开发约定](architecture-and-decisions.md)。本文件只保留接手下一轮工作所需的信息，避免重复记录完整架构。

## 交接规则

- 开始工作前先阅读 `AGENTS.md` 和本文件；
- 接手时检查 Git 状态和最近提交；
- 一次只推进一个边界明确的任务；
- 工作完成后更新本文件中的当前状态；
- 长期有效的新决定同步写入架构文档；
- 完成测试、提交并推送后才算正常交接；
- 不保留无说明的未提交修改。

## 建议下一步

开始实现 **采集任务模块的最小后端**，先不要接入真实供应商。

建议第一步包含：

1. 定义采集任务类型：`INITIAL`、`INCREMENTAL`、`REPAIR`、`REPLACE`；
2. 定义任务状态，但第一版只需要支持创建和规划阶段；
3. 首次采集要求明确的开始、结束日期；
4. 只有 `ACTIVE` 数据集可以创建采集任务；
5. 增量任务先保留 Planner 接口，等待 Catalog 后再真正计算缺口；
6. 使用模拟数据集和测试验证任务创建；
7. 后端稳定后再添加采集任务前端页面。

不要在这一阶段接入 TuShare 密钥、百度网盘账号或真实 L2 文件。

## 已知问题与注意事项

- 当前只有 Schema v1，尚未实现已启用数据集的新 Schema 版本；
- 当前 SQLite 表由 `create_all` 建立，尚未引入 Alembic；
- FastAPI 测试会出现 Starlette 关于 `httpx` 的弃用警告，不影响现有测试结果；
- 真实数据必须存放在仓库之外；
- 当前前后端需要分别启动；
- 文件分区、历史修订和 Catalog 表结构仍属于待定设计；
- 增量采集不能最终实现为“最大日期加一天”，必须由交易日历和 Catalog 缺口共同决定。
