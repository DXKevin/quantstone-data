# Agent 工作交接

本文档是 Codex 与 DeepSeek Harness 在同一个项目目录中串行接力的当前状态记录。

长期架构与项目原则见 [项目架构、设计原则与开发约定](architecture-and-decisions.md)。本文件只保留接手下一轮工作所需的信息，避免重复记录完整架构。

## 交接规则

- 开始工作前先阅读 `AGENTS.md` 和本文件；
- 接手时检查 Git 状态和最近提交；
- 一次只推进一个边界明确的任务；
- 工作完成后更新本文件中的当前状态；
- 长期有效的新决定同步写入架构文档；
- 完成测试、提交并推送后才算正常交接；
- 不保留无说明的未提交修改。

## 已知问题与注意事项

- 当前只有 Schema v1，尚未实现已启用数据集的新 Schema 版本；
- 当前 SQLite 表由 `create_all` 建立，尚未引入 Alembic；
- FastAPI 测试会出现 Starlette 关于 `httpx` 的弃用警告，不影响现有测试结果；
- 真实数据必须存放在仓库之外；
- 当前前后端需要分别启动；
- 手动上传目前没有文件大小上限，应在真实大文件使用前增加可配置限制；
- `STAGED` 文件尚未解析、校验或发布；
- stock_basic 首版只采集当前上市状态 `L`；完整状态需要任务参数和限流调度；
- 文件分区、历史修订和 Catalog 表结构仍属于待定设计；
- 增量采集不能最终实现为“最大日期加一天”，必须由交易日历和 Catalog 缺口共同决定。
- `tushare.cn.stock.trade_cal` 已发布 2010-01-01 至 2027-12-31 的正式快照，共 6,574 行；
- 旧 daily 任务 `ad4999e3-7e63-4368-8294-ddd3998f4997` 保留审核失败记录；后续任务已通过交易日历跳过 2024-02-09 至 2024-02-18 的休市日期；
- daily 增量任务 `3d3b23ff-761a-4973-8973-fbf3be6b0b75` 已成功发布 2024-02-19 至 2024-04-30 的 50 个交易日，随后在 2024-05-06 命中 TuShare `daily` 每分钟 50 次限制而失败；
- daily 已发布日增量，但年度合并尚未实现；
- daily 增量需在限流框架下新建任务，从 Catalog 最新分区 2024-04-30 之后继续；
- 采集执行仍同步占用 HTTP 请求，长日期范围会阻塞数分钟，尚未引入后台任务队列；
- 限流器只存在于进程内，多进程部署需要改为共享限流；
